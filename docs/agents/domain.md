# Domain documentation

Read `CONTEXT.md` for the project's vocabulary and `docs/adr/` for design decisions. Use the defined terms consistently. When a term or decision no longer fits, explain the mismatch and propose an update; the glossary records choices, not proof that those choices are right.

If a term is missing, first check whether an existing one expresses the same concept. Add a definition when it resolves a real ambiguity. Keep decision records focused on the decision, its rationale, alternatives and consequences.
