# Integration-first testing on real runtimes, no mocks

Tests exercise the public API as outside callers: Vitest runs in Node and starts the hub twice over, as a Worker from its Wrangler config in real workerd with Wrangler's `createTestHarness()` and as a Node process as its Docker image runs it, and runs the same suite against each, alongside a real Postgres from Testcontainers, and starts the Node runner in the test process, dialling the hub's URL over a real WebSocket as on a host. Unit tests are written only for dense pure logic that is awkward to reach through the API, and for contracts beneath it that their owner defines a suite for: each Execution environment runs pi-durable's environment conformance cases next to its code, as pi-durable's own environments do, and tests what pi-durable's tools rely on beyond those cases, since a job reaches them only through a model's tool calls. Pi and the execution environments are never mocked; pi-ai's faux model stands in for the LLM so runs stay deterministic and free.

Container tests (real programs through the container backend) live in the same suite but are tagged and skipped by default, because they need Docker and an image build: the default `vp test` run excludes them, a separate run includes them, and CI runs them on container-related changes and nightly.
