# Vite+ as the toolchain, defaults first

The repo is generated with `vp create` and uses Vite+ (`vp check`, `vp test`, `vp pack`, `vp run`, commit hooks) with its defaults; the hub is generated by create-cloudflare into `apps/`, and the runner and the CLI by `vp create vite:library` into `apps/` and `packages/`. Cloudflare's `@cloudflare/vitest-plugin`, for tests that run inside a Worker, supports the Vitest that Vite+ ships, which removed the reason for ADR 0002; the hub's tests start the hub Worker from Node with Wrangler's test harness instead (ADR 0003). We take tool defaults as they come and deviate only by explicit decision, so the setup stays easy to upgrade and to recognise.

Approved deviations:

- `minimumReleaseAge: 1440` with no exemptions, including for Vite+ itself: a one-day delay is the cheapest guard against a compromised release for software that runs unattended with users' API keys.
- `allowBuilds` approving `workerd` and `esbuild`, which wrangler needs, and denying `cpu-features`, `protobufjs` and `ssh2`, whose install scripts Testcontainers does not need, `@google/genai`, whose install script does nothing, and `@mongodb-js/zstd` and `node-liblzma`, just-bash's optional codecs, which would need a C++ toolchain wherever the Runner is installed; pnpm requires an explicit answer.
- The hub follows Vite+'s templates where they differ from create-cloudflare's: it is an ES module (`"type": "module"`) and import other files by their `.ts` names (`allowImportingTsExtensions`). Settings the scaffold adds that change nothing here are removed: JSX and JavaScript options, TypeScript defaults, ignore rules the root `.gitignore` already covers, the `start` script that repeats `dev`, and the Wrangler config's commented-out examples other than Smart Placement.
- The runner is an application, not a library: it is private, without the template's publishing pieces (`publishConfig`, `files`, `bumpp`, type declarations). The hub's system tests exercise it (ADR 0003); its own `test` script runs its Execution environments' tests: pi-durable's conformance cases, and what pi-durable's tools rely on beyond them, such as a file's byte-order mark surviving an edit.
- The hub's test files run one at a time (`fileParallelism: false`), because they share one Postgres and each clears it before starting.

This supersedes ADR 0001 and ADR 0002. The private `contract` and `runner` packages export their TypeScript source: they are never published, and everything that uses them compiles TypeScript itself (Wrangler for the Workers, Vitest for tests, `vp pack` for the CLI, and Node, which strips the types when the tests start the hub, a Runner or the CLI from source), so checks and tests run without building them first and the scaffold's `ready` script works unchanged. `erasableSyntaxOnly` and `verbatimModuleSyntax` in each package keep its code to the TypeScript that Node can strip, as Node's docs advise: no syntax to compile, and each import of a type marked as one. `contract` has no build. The runner's `vp pack` build exists only to start a Runner directly, and it bundles `contract` (`deps.alwaysBundle`), so the built Runner never loads TypeScript. A package that is published is built with `vp pack`. The CLI is published as its command alone, with no library export (ADR 0004) and so no type declarations. In the workspace its `bin` points to its source (tsdown's `devExports`), so the hub's tests run the command unbuilt; its `publishConfig` points the published `bin` at the build, which pnpm applies when it packs and npm does not, so it is packed and published with pnpm (`vp pm publish`). Its build bundles everything the command imports, as create-vite does: the packages from npm it imports itself, which it lists as dev dependencies, and `contract` with what `contract` imports. Installing it installs one package, with the versions its tests ran, and `rollup-plugin-license` writes the bundled packages' licences to `dist/THIRD_PARTY_NOTICES.txt`.
